# 实现边界

## 本地数据

SQLite 的 `plans` 保存已核对的计划；`dose_events` 以追加事件保存 TAKEN、SKIPPED、UNDONE，最新事件决定当前登记状态。计划 ID 与计划时间构成剂次键。重复点击同一剂次不会重复登记；撤销之后可以重新填写正确的实际时间。

每条事件保存当时的药名、剂量、计划时间、实际时间和登记时间。暂停、恢复和新建计划不覆盖历史。`snoozes` 保存稍后提醒，重启时只恢复将来尚未登记的通知。

数据库操作在 IO 调度器串行执行，刷新通过 StateFlow 推送到界面。当前数据库版本为 2（只追加 inbox_drafts 表）；后续升级必须增加迁移，不能使用清库式升级。

## 排程

`core` 不依赖 Android，可独立验证日期、时区、疗程与间隔。每日计划按当地钟点生成；间隔计划保留 Instant 锚点，避免跨午夜或夏令时后改变实际间隔。

夏令时跳时中不存在的每日钟点不自动平移；核心返回缺失钟点供今日页面提示人工核对，只对存在的钟点生成独立剂次，并按实际 Instant 排序。

普通进程启动和页面刷新保留已到期、正在交付的稍后提醒，不取消其闹钟；接收器在仓库锁内校验归属、原始剂次、延后时间和记录状态后单次领取。开机或时间恢复明确清理过期稍后提醒，避免补发。

每个启用计划只向系统注册下一次主闹钟。触发时先检查原计划、有效剂次与当前记录，再发送通知或写入事件，最后安排下次。开机、修改系统时间、切换时区、更新安装包以及重新获得精确定时权限后重排。过去的剂次只留给人工核对，不自动补发。

Android 12+ 精确闹钟和 Android 13+ 通知权限分别检查。精确权限缺失时使用非精确闹钟并在 UI 提示延迟风险。没有通过常驻服务或反复唤醒来绕过系统限制。

## MCP 草稿流程

默认由 ChatGPT 在会话中整理原文，通过 OAuth 授权的 MCP 工具保存待核对草稿。服务器单进程原子落盘，手机主动分页领取并再次检查原文证据，核对后在同一 SQLite 事务中写入计划、去重标记与待补发回执。服务端不能启用手机提醒，也不读取或登记服药事件。已确认的提醒仍由本地排程。详细协议、权限、持久化和验收边界见 [MCP 文档](mcp.md)。

## 计划编辑

药箱中编辑已有计划，保留计划 ID 和启用／暂停状态；保存前再次人工核对。事务只更新计划并移除旧稍后提醒，历史事件及草稿与计划的关联保持原样。通过原计划快照检查拒绝过期编辑，避免覆盖其他操作。提交后取消旧系统闹钟与已显示通知，只重排未来提醒；系统排程失败与本地保存成功分别提示。

每日计划使用当前时区钟点。间隔计划编辑时，开始日期与首次钟点未改变则保留原 Instant，避免切换时区后无意平移间隔锚点。修改后的今日安排会重新计算，已有历史快照不会随之重写，需由用户结合实际记录核对。

## 草稿校验与凭据

每个非空字段必须能在对应 sourceQuote 中找到；sourceQuote 必须出现在输入原文。服务和手机都执行这项校验。机械校验无法证明药物与用法的关联一定正确，最终仍需人工逐项核对，不能自动启用提醒。

手机只保存自有 MCP 服务地址与访问口令。口令以 Android Keystore 管理的 AES/GCM 密钥加密，并用 AAD 绑定服务地址；更换地址需重新填写。保存前先校验，再原子写入。请求禁止跟随重定向，限制响应大小，不透传含敏感信息的错误正文。

应用和服务均不包含模型 API 调用或整理中转。升级清理废弃模型配置，保留 MCP 连接与 Keystore 密钥；旧服务地址和加密口令仍可用于迁移。健康检查只验证 MCP 本地配置，不调用模型。
