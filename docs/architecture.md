# 实现边界

## 本地数据

SQLite 的 `plans` 保存已核对的计划；`dose_events` 以追加事件保存 TAKEN、SKIPPED、UNDONE，最新事件决定当前登记状态。计划 ID 与计划时间构成剂次键。重复点击同一剂次不会重复登记；撤销之后可以重新填写正确的实际时间。

每条事件保存当时的药名、剂量、计划时间、实际时间和登记时间。暂停、恢复和新建计划不覆盖历史。`snoozes` 保存稍后提醒，重启时只恢复将来尚未登记的通知。

数据库操作在 IO 调度器串行执行，刷新通过 StateFlow 推送到界面。当前数据库版本为 1；后续升级必须增加迁移，不能使用清库式升级。

## 排程

`core` 不依赖 Android，可独立验证日期、时区、疗程与间隔。每日计划按当地钟点生成；间隔计划保留 Instant 锚点，避免跨午夜或夏令时后改变实际间隔。

每个启用计划只向系统注册下一次主闹钟。触发时先检查原计划、有效剂次与当前记录，再发送通知或写入事件，最后安排下次。开机、修改系统时间、切换时区、更新安装包以及重新获得精确定时权限后重排。过去的剂次只留给人工核对，不自动补发。

Android 12+ 精确闹钟和 Android 13+ 通知权限分别检查。精确权限缺失时使用非精确闹钟并在 UI 提示延迟风险。没有通过常驻服务或反复唤醒来绕过系统限制。

## AI 流程

安卓默认直接调用智谱 GLM-4.7-Flash，固定官方基础地址和具体型号，返回的模型标识必须一致。内置入口不接受任意地址或型号，不自动回退。只解析正常结束的最终文本，不读取推理内容。免费政策由平台决定，客户端型号校验不能保证平台未来的价格不变。

API 密钥由用户在手机填写，以 Android Keystore 管理的 AES/GCM 密钥加密保存，不放入 APK、日志、备份或数据导出。智谱密钥、其他 API 密钥和服务口令分开保存。密钥密文通过 AAD 绑定保存时的 API 基础地址；更换地址需重新填写对应密钥。保存前先完成地址、模型与凭据校验，之后一次写入，避免部分设置生效。

只有明确同意导入时才上传输入文字，确认页展示接收方。请求禁止跟随重定向，限制响应大小，错误不透传提供方正文。手机无需电脑或 Node 服务即可完成 GPT 导入。

自有 Node 服务作为可选连接方式保留，支持 Docker Compose 部署；该模式下提供方密钥留在服务环境变量，手机只保存加密的服务口令。新部署默认调用智谱官方 GLM-4.7-Flash，固定地址和型号、校验响应型号、不回退；保留旧 OpenAI 环境配置兼容，不跨提供方复用密钥。手机不能覆盖服务端模型、地址和密钥。服务不保存医嘱，不接收计划数据库、不同步历史，不负责用药提醒。旧版已配置的手机服务连接保持原模式，服务口令和直连 API 密钥分开保存。

智谱入口（手机直连与服务端）调用 Chat Completions，要求 JSON 对象，并在指令中提供完整字段结构；继续检查字段类型、原文证据和缺失项。其他 API 直连和 Node 服务的 OpenAI 模式调用 Responses API，要求 JSON Schema，并设置 `store:false`。这项参数不是对所有服务端数据保留行为的零保留承诺。模型拒绝、未完成输出和无法校验的字段都返回错误，不生成假草稿。服务端同样禁止重定向，限制上游正文大小，不透传上游错误；健康检查只验证本地配置，不调用模型。

每个非空字段必须能在对应 sourceQuote 中找到；sourceQuote 必须出现在输入原文。手机全部连接模式都执行这项校验，不直接信任服务返回结果。这个机械校验只用于减少新增内容，无法证明药物与用法的关联一定正确，所以最终仍要求逐项人工核对。提取接口不计算具体提醒钟点，不写入手机计划。

初版只做文字导入。照片识别与 PC 数据同步后续实现。
