## 安装与基础体验

1. 安装开发 APK，首次打开应为空状态，没有预先创建的药物。
2. 手动添加一条用于提醒测试的虚拟计划，不据此实际服药。核对开关未勾选时不能保存。
3. 设置多个固定钟点，检查排序和今日展示；切换日期应展示对应疗程的剂次。
4. 登记一次服用，重复操作同一剂次不应产生第二条记录。
5. 从历史撤销并重新补录实际时间；原登记及撤销都应仍可见。
6. 暂停计划后不应再出现通知；历史仍在。恢复时不集中补发过去提醒。
7. 导出 JSON，检查含计划及全部操作历史，不含访问口令。

## 系统提醒

1. 开启系统通知、允许闹钟和提醒。检查 ColorOS 应用详情内通知类别、电池使用与后台活动设置。
2. 运行 15 秒测试提醒，分别检查前台、回桌面、锁屏和断网。
3. 添加几分钟后的虚拟计划；回桌面后等待，记录实际通知时间及计划时间差。
4. 从通知选择已服用，应只登记一次，应用打开后能看到同一记录。
5. 从通知选择稍后提醒，10 分钟后应再次通知，原计划钟点保持不变。
6. 在稍后提醒等待期间先在 App 内完成登记，后续通知应取消。
7. 在未来提醒之前重启，解锁后确认计划重新注册并正常提醒。
8. 撤销精确定时权限，页面应标示未就绪与可能延迟；恢复授权后重新安排。
9. 关闭通知权限，页面应提示通知未开启；不得显示一切就绪。
10. 手动强行停止、关闭手机或开启勿扰后检查系统限制，不能据此宣称通知始终必达。

## AI 联调

1. 在手机设置选择智谱 GLM-4.7-Flash，填写用户自己的智谱 API Key，手机直连无需电脑在线。内置模式应显示固定型号和官方接收方；不应出现任意型号编辑或自动回退。
2. 未同意上传时不应调用接口；无效密钥显示清楚错误，不显示提供方原始错误正文。
3. 输入只含虚拟药名的测试医嘱，确认提取结果可逐项与原文核对。
4. 缺失剂量、频次或疗程时应保留缺失项，不自动填入常见用法。
5. 明确“每日三次”的文字不应自动创建每 8 小时计划。
6. 解析草稿本身不得产生提醒；核对并手动填写钟点、日期后才保存。
7. 接口不可达或密钥未配置时显示错误，手动添加、本地提醒及记录仍能使用。
8. 清除本机 API 密钥后，已有提醒和记录不受影响；重新导入需再次填写。
9. 可选自有服务模式单独配置本机 `.env` 和服务口令，启动服务后可用 USB `adb reverse` 联调；此步骤不属于手机直连的前提。
10. 内置智谱模式必须请求 `glm-4.7-flash`。用模拟响应返回其他型号、空型号、截断输出或工具请求，应停止导入，不重试其他型号。真实调用后在智谱控制台核对型号、用量和费用，客户端不保证平台未来的定价不变。
